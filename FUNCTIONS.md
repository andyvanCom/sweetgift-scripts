# SweetGift Functions

Документ описывает серверные функции, RPC-процедуры и плановые задачи платформы SweetGift.

Последнее обновление: 2026-07-30

---

# Назначение

FUNCTIONS.md является техническим справочником автоматических процессов платформы.

Документ содержит:

- Edge Functions;
- RPC-функции;
- плановые задачи;
- последовательность ночной обработки;
- назначение основных процедур;
- зависимости между функциями.

Документ не содержит:

- секретов;
- токенов;
- паролей;
- закрытых URL;
- service role key;
- SMTP-настроек;
- внутренней авторизационной информации.

---

# Общая схема

```text
Источники данных
      │
      ▼
Edge Functions
      │
      ▼
PostgreSQL
      │
      ├── RPC
      ├── Aggregation
      ├── SEO
      └── Recommendations
      │
      ▼
Frontend Modules
```

# Edge Functions

## gift-selector-request

### Назначение

Отправка запроса на изготовление корзин, когда подбор по выбранному составу
не нашёл готовых товаров.

### Принимает

- выбранные ингредиенты;
- количество корзин;
- бюджет на одну корзину;
- имя;
- телефон;
- email;
- необязательный комментарий клиента;
- согласие на обработку данных.

### Особенности

- данные не сохраняются в базе;
- письмо отправляется через существующий SMTP;
- запросы принимаются только с домена SweetGift;
- применяются серверная валидация, ограничение частоты и антибот-поле.

## assign_missing_article_seo_topics_batch

### Назначение

Пакетно назначает SEO-темы активным статьям, у которых не заполнено
`seo_topic_title`.

### Алгоритм

1. Берёт не более `p_limit` статей; значение по умолчанию — 15.
2. Ищет наиболее точное совпадение в `seo_topic_queries`.
3. Для статей без совпадения использует нормализованный заголовок как fallback.
4. Возвращает количество обработанных статей, совпадений с семантическим ядром,
   fallback-назначений и оставшихся статей без темы.

Edge Function повторяет вызов небольшими пакетами. Это предотвращает
`statement timeout` при росте индекса статей и семантического ядра.

## get_gift_selector_catalog

### Назначение

Единая публичная read-only выгрузка для страницы:

```text
/podbor-po-sostavu
```

Общая внутренняя функция `get_gift_selector_catalog_for` также используется
RPC `get_gift_box_selector_catalog` для отдельной страницы:

```text
/podbor-naborov-po-sostavu
```

В неё входят только разделы `novogodnie-nabory`, `ng-gift-box`,
`gift-nabor` и `box-s-lomom`. Разделы подарочных корзин не включаются,
даже если товары в них имеют похожий состав.

Новые разделы, в slug которых есть `nabor`, `gift-box` или префикс `box-`,
подхватываются автоматически.

### Источники

- `products_catalog`;
- `product_ingredients`;
- `product_events`.

### Результат

Возвращает одним JSON-ответом:

- доступные товары со ссылкой, изображением, ценой и составом;
- канонические теги ингредиентов каждого товара;
- полный список тегов и количество товаров для каждого;
- рассчитанный индекс популярности.

После ответа фильтрация выполняется полностью в браузере.

## get_article_products

### Назначение

Возвращает подарочные корзины для Alias статьи Tilda на основании
серверной конфигурации `article_product_filters`.

### Источники

- `article_product_filters`;
- `article_product_cache`;
- `products_catalog`;

Таблицы `product_ingredients` и `product_events` используются при ночном
построении кеша, а не во время публичного запроса.

### Безопасность

Клиент передаёт только Alias. Тип и значение фильтра выбираются на сервере.
Прямое чтение таблицы конфигурации для `anon` и `authenticated` запрещено.

### Результат

- заголовок и подзаголовок блока;
- до `limit_count` доступных подарочных корзин;
- совпавшие ингредиенты;
- существующая метрика популярности;
- ссылки внутри соответствующего SEO-кластера.

## refresh_article_product_cache

### Назначение

Заранее рассчитывает соответствия Alias статьи и товаров, чтобы публичный
frontend получал готовую подборку без тяжёлой фильтрации состава.

### Особенности

- одинаковые определения фильтров рассчитываются один раз и затем
  распространяются на все соответствующие Alias;
- поддерживаются точные ингредиенты, вхождения, альтернативы через `|` и
  обязательные группы через `&&`;
- замена кеша выполняется транзакционно: при ошибке прежние данные остаются
  доступны;
- параллельные пересчёты блокируются advisory lock;
- результат записывается в `article_product_cache`.

---

## request_article_product_cache_refresh

### Назначение

Ставит ручной пересчёт товарных подборок из админ-панели в очередь `pg_cron`
и сразу возвращает управление frontend.

### Особенности

- устраняет `statement timeout` синхронного PostgREST-вызова;
- не создаёт второе задание, если пересчёт уже выполняется или поставлен в
  очередь;
- временное cron-задание удаляет себя перед началом тяжёлого пересчёта;
- фактическую работу по-прежнему выполняет проверенная функция
  `refresh_article_product_cache()`;
- результат выполнения отображается в `system_job_logs` и метриках админки.

## sync_honey_article_filters

### Назначение

Синхронизирует опубликованные статьи медового SEO-кластера с существующей
таблицей `article_product_filters`.

### Особенности

- сохраняет прежние фильтры;
- создаёт и обновляет фильтры только для переданных Alias;
- использует точные подгруппы: сыр, напитки, орехи, фрукты, крем-мёд,
  медовые продукты, сезонные и подарочные материалы;
- вызывается после импорта индекса статей.

## sync_nut_article_filters

### Назначение

Синхронизирует опубликованные статьи орехового SEO-кластера с существующей
таблицей `article_product_filters`.

### Особенности

- принимает только явный список из 100 утверждённых Alias;
- распознаёт миндаль, фундук и лесной орех, грецкий орех, кешью, кедровые
  орехи, арахис, фисташки, пекан и кокос;
- не использует широкое совпадение по слову `ореховый`, поэтому сыр с
  ореховым вкусом не считается ореховым продуктом сам по себе;
- для сочетаний использует обязательные группы `&&`: орехи и сыр, мёд,
  шоколад, кофе, чай, фрукты, сухофрукты или мясные деликатесы;
- вызывается после медовой синхронизации, поэтому общие Alias нового
  орехового кластера получают ореховую группировку и перелинковку;
- готовые результаты по-прежнему строятся функцией
  `refresh_article_product_cache()`.

## sync_builder_day_article_filters

### Назначение

Синхронизирует 30 опубликованных статей кластера «День строителя» с таблицей
`article_product_filters`.

### Профили

- общие и коммерческие статьи — популярные продуктовые корзины;
- мужчина, муж, парень и дедушка — гастрономические, сырно-мясные, кофейные
  и ореховые составы;
- женщина — фруктовые, сырные и сладкие корзины;
- руководитель, директор, начальник и VIP — икра, краб, осётр, фуа-гра,
  трюфель, хамон и другие премиальные признаки;
- коллега, сотрудники и работники — универсальные чайные, кофейные,
  шоколадные и ореховые составы;
- партнёры — деловые сырные и деликатесные корзины;
- оригинальные и прикольные подарки — дичь, деликатесы и экзотические
  фрукты.

Фиктивный тег `строитель` не создаётся. Получатель и повод отсутствуют в
структурированных данных товаров, поэтому они безопасно отображаются через
профили реальных ингредиентов, а порядок товаров задаёт существующая
популярность.

## sync_coffee_article_filters

### Назначение

Синхронизирует 100 опубликованных статей кластера «Кофе» с таблицей
`article_product_filters` и существующим ночным кешем товарных подборок.

### Правила

- кофе в зёрнах, молотый и растворимый кофе используют фактические варианты
  из `product_ingredients`;
- сочетания с шоколадом, орехами, мёдом, сыром, фруктами, сухофруктами,
  печеньем, конфетами и мясными деликатесами используют обязательную
  AND-логику;
- мужские, женские, корпоративные и деловые статьи получают разные профили
  реального состава;
- Arabica, Robusta, большинство стран происхождения, светлая и средняя
  обжарка, помол и способы приготовления сейчас не хранятся структурированно,
  поэтому для них используется безопасная общая подборка с кофе;
- для сочетания кофе с фисташками также используется кофейная подборка,
  поскольку в доступном каталоге пока нет такого пересечения;
- склонения названий шоколада учитываются по фактическому русскому составу;
- фиктивные характеристики не создаются, используются только доступные
  товары, существующая популярность и лимит до 12 карточек.

## request_article_product_cache_refresh

Ручной пересчёт остаётся асинхронным и не блокирует админку. Одноразовый
`pg_cron`-процесс получает отдельный лимит 10 минут, потому что полный кеш
всех SEO-кластеров уже превышает общий двухминутный `statement_timeout`.
Старый кеш сохраняется до успешного завершения нового расчёта.

## apply_coffee_article_filter_overrides

После основной синхронизации сохраняет прежние Alias и уточняет только три
темы по фактическим названиям товаров:

- `aromatnyy-kofe-v-podarok` — Vanilla, Truffle, Cardamom, Mokka и Noir;
- `kofe-dlya-espresso` — Egoiste Espresso, Illy Espresso и Lavazza Espresso;
- `italyanskiy-kofe-v-podarok` — Illy, Bialetti, Lavazza и Piazza Del Caffe.

Остальные информационные темы без структурированного признака продолжают
использовать безопасную общую подборку доступных корзин с кофе.

# Scheduled Jobs

Плановые задачи выполняются средствами PostgreSQL и Supabase.

## import-yml-products-daily

### Назначение

Ежедневное обновление товарного каталога.

### Выполняется

Ежедневно в 04:00 UTC перед остальными этапами ночной обработки.

Дополнительно сверяет каталог с полным YML и помечает отсутствующие в источнике
товары недоступными.

## import-articles-index-daily

### Назначение

Ежедневное обновление индекса статей.

### Выполняется

Ежедневно в 04:30 UTC, после импорта товаров и до классификации статей.

Daily-режим обрабатывает весь список новых и изменённых статей за один запуск,
разбивая его на последовательные Edge-запуски по 100 записей. После успешного
пакета следующий запускается автоматически. Отсутствующие в sitemap статьи
помечаются неактивными.

## classify-articles-daily

### Назначение

Ежедневная автоматическая классификация статей.

### Выполняется

Ежедневно в 04:45 UTC, после импорта статей.

### Ограничение времени

SEO-темы назначаются небольшими пакетами. Тяжёлые пересчёты не запускаются
внутри классификатора, что удерживает Edge Function и SQL-запросы в пределах
runtime и statement timeout.

# Night Pipeline

Текущая последовательность:

```text
Импорт товаров
      ↓
Импорт статей
      ↓
Классификация статей
      ↓
Кеш товарных подборок статей
      ↓
Пересчёт SEO-блоков товаров
      ↓
Пересчёт рекомендаций товаров для статей
      ↓
Ежедневный отчёт
```

Популярные списки дополнительно обновляются каждый час.

# Надёжность

Тяжёлые процедуры выполняются отдельными cron-задачами с интервалом 15 минут.
Повторный ручной запуск должен быть идемпотентным и не создавать дубли.

---

# Требования к функциям

Каждая функция должна:

- безопасно обрабатывать повторный запуск;
- не создавать дубли;
- возвращать понятный статус;
- сообщать количество обработанных записей;
- фиксировать ошибки;
- не раскрывать секреты;
- не хранить персональные данные без необходимости.

---

# Обработка ошибок

Ошибки должны:

- возвращаться в структурированном виде;
- попадать в технический отчёт;
- не оставлять данные в частично обновлённом состоянии;
- позволять повторный запуск задачи.

Ошибки фоновых задач записываются в отдельный журнал выполнения.

---

# Логирование

# Order Analytics

## track_product_order

Принимает JSON успешно оформленного заказа, проверяет обязательный `order_id` и
от 1 до 100 позиций, затем идемпотентно записывает их в `product_orders`. Событие
`purchase` создаётся только для действительно добавленной позиции, поэтому повтор
запроса не искажает статистику.

Признак подарка трактует вопрос `SamSebe` как «заказ себе»: ответ `Нет`
записывается как `is_gift = true`, ответ `Да` — как `is_gift = false`.
Серверный триггер повторяет нормализацию для защиты от старого CDN-кеша.

Доступна ролям `anon` и `authenticated`; сама таблица им недоступна.

# Admin Dashboard

## admin-dashboard

Закрытая серверная страница аналитики и управления SweetGift.

Показывает:

- заказы, выручку, средний чек и количество проданных товаров;
- популярные товары и категории за 7, 30 или 90 дней;
- последние обезличенные заказы;
- состояние обязательных этапов pipeline;
- текущий текст ежедневного отчёта.

Позволяет вручную запустить импорт товаров, импорт статей, классификацию и
формирование почтового отчёта. Вход выполняется через Supabase Auth, а сервер
допускает только пользователей с `app_metadata.role = admin`. Pipeline-секрет и
service-role ключ никогда не передаются браузеру.
