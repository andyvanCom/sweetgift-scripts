# SweetGift Roadmap

Актуально на 2026-09-02.

## Уже работает

### Каталог и состав

- автоматический YML-импорт товаров;
- базовые товары и отдельные варианты/издания;
- структурированный состав и правила тегирования;
- CSV-снимок Tilda для проверки остатка и срока «под заказ»;
- исключение специализированных алкогольных разделов из публичных подборок.

### Статьи и SEO

- импорт Tilda «Потоки»;
- темы и сущности статей;
- товары внутри статей по `data-alias`;
- два независимых контейнера и общие Promise для одинаковых Alias;
- ночной `article_product_cache`;
- статические JSON через GitHub/jsDelivr с Edge/RPC fallback;
- «Читайте также» с реальными уникальными анкорами и компактным раскрытием;
- статьи в карточках товаров;
- кластеры сыров, мёда, орехов, кофе, чая, икры, фруктов, Нового года, подарочных идей, школы и Дня строителя.

### Пользовательские инструменты

- подбор корзин по составу;
- подбор наборов/боксов по составу;
- форма запроса отсутствующего сочетания;
- единый квиз с ветками корзина, бокс, клубника/букет;
- ранний показ результатов после первого ответа;
- системный шаринг и URL состояния.

### Аналитика и эксплуатация

- просмотры и активность товаров/статей;
- обезличенная аналитика заказов, промокодов, доставки и подарочного признака;
- рейтинги товаров и статей;
- административная панель с одноразовым кодом;
- ночной pipeline и ежедневный email-отчёт;
- предупреждение о размере базы от 350 MB;
- retention подробных событий 180 дней и админ-метрик 90 дней;
- поиск и выдача фактов о товарах для мини-приложения/NeuroMaria.

## Ближайшие задачи

### P1 — надёжность данных

- устранить хранение служебных секретов непосредственно в определениях cron и перевести вызовы на безопасное получение из Vault/Secrets;
- добавить автоматическую сверку файлов миграций GitHub с историей Supabase;
- контролировать, что GitHub Action экспорта запускается после завершения серверного кеша, а не одновременно с ним;
- добавить алерт, если static manifest старше последнего успешного серверного пересчёта;
- отслеживать доступность YML, Tilda articles index, Edge Functions и email-доставки.

### P1 — качество каталога

- повысить покрытие нормализованных ингредиентов и категорий;
- регулярно проверять ложные теги и морфологические совпадения;
- объяснять причину `available=false` в админке: YML, CSV, вариант, удаление или ошибка импорта;
- контролировать дубли Tilda URL/ID и не считать варианты отдельными товарами;
- добавить отчёт по товарам без состава и без сущностей.

### P1 — рекомендации

- измерять клики и конверсию каждого блока;
- добавить управляемое разнообразие, чтобы соседние статьи не получали одинаковые 12 товаров;
- продолжить улучшение сочетания состава, цены, категории и популярности;
- добавить диагностику пустых Alias и нерелевантных результатов до публикации кеша.

## Следующий этап

### Bought Together

Строить совместные покупки только после накопления достаточного количества обезличенных заказов. Не делать выводы из единичных заказов.

### Frontend health

Собирать ошибки loader/модулей, версию manifest, время получения данных и долю успешных fallback. Не хранить персональные данные и полный user agent без необходимости.

### Улучшенный поиск

Текущий `miniapp_search_products_v1` — поиск по точному и подстрочному названию. Для устойчивости к опечаткам отдельно спроектировать trigram/full-text поиск, оценить индексы, нагрузку, русский язык и false positives. Не называть текущий LIKE-поиск нечётким.

### Админка

- понятные объяснения метрик и статусов;
- история запусков и длительности;
- безопасный перезапуск отдельных этапов;
- прогресс длительных пересчётов;
- диагностика конкретного товара, статьи или Alias.

## Долгосрочно

- качественный AI-поиск и помощник по каталогу;
- персонализация без хранения лишних персональных данных;
- граф знаний «товар — ингредиент — получатель — повод — статья»;
- динамические SEO-разделы только из подтверждённых каталожных признаков;
- A/B-тестирование квиза, карточек и рекомендаций;
- мониторинг бизнес-метрик по каналу, категории и периоду.

## Не планируется без отдельного решения

- перенос оформления заказа из Tilda;
- генерация фиктивных ингредиентов ради SEO;
- хранение контактов покупателей в аналитических таблицах;
- синхронные тяжёлые пересчёты при открытии страницы;
- новая параллельная архитектура вместо существующих filters/cache/RPC.

## Критерии завершения любой задачи

1. Решение использует существующую архитектуру либо обоснованно расширяет её.
2. Есть проверка на живом сценарии.
3. Нет утечки секретов или персональных данных.
4. Миграции, Edge Functions и GitHub согласованы.
5. Frontend version увеличена при изменении JS.
6. Обновлены документы и changelog.
7. Изменения находятся в `origin/main`.
